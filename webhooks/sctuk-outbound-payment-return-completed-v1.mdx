---
title: "Cross-border Outbound Payment Return Completed webhook"
version: 1
webhook: true
---

This webhook confirms that an outbound SEPA Credit Transfer (SCT) payment you sent has been returned. It includes ISO 20022 compliant details identifying the original payment and the returned amount.

#### Request body

```json
{
  "Type": "Payments.CrossBorder.OutboundPaymentReturnCompleted",
  "Version": 1,
  "Payload": {...},
  "Nonce":
}
```

#### Payload Fields

| Field                    | Type   | Format | Required | Min-Max length | Pattern | Description                                                                                                                |
| ------------------------ | ------ | ------ | -------- | -------------- | ------- | -------------------------------------------------------------------------------------------------------------------------- |
| `OriginalPaymentId`      | string | uuid   | Yes      | -              | -       | A unique identifier assigned by ClearBank referencing the payment instruction for the original outbound payment.           |
| `OriginalTransactionId`  | string | uuid   | Yes      | -              | -       | A unique identifier assigned by ClearBank referencing the debit transaction that relates to the original outbound payment. |
| `TransactionId`          | string | uuid   | Yes      | -              | -       | A unique identifier assigned by ClearBank referencing the credit transaction that relates to the returned payment.         |
| `ReturnId`               | string | uuid   | Yes      | -              | -       | A unique identifier assigned by ClearBank referencing the return message.                                                  |
| `OriginalMessageIdentification` | string | -      | Yes      | 1-35           | -       | Point to point reference assigned by the original instructing party to unambiguously identify the original message.       |
| `TransactionInformation` | object | -      | Yes      | -              | -       | Information concerning the original transaction, to which the return refers. Refer to the 'TransactionInformation' table.       |

##### TransactionInformation

| Field                               | Type   | Required | Min-Max length | Pattern | Description                                                                                                                                                               |
| ----------------------------------- | ------ | -------- | -------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OriginalUETR`                      | string | Yes      | -              | -       | Universally unique identifier to provide the original end-to-end reference of a payment transaction. Format: `uuid`.                                                      |
| `OriginalEndToEndIdentification`    | string | Yes      | 1-35           | -       | Unique identification, as assigned by the original initiating party, to unambiguously identify the original transaction.                                                  |
| `OriginalInterbankSettlementAmount` | object | Yes      | -              | -       | Amount of money moved between the instructing agent and the instructed agent, as provided in the original instruction. Refer to the 'ActiveOrHistoricCurrencyAndAmount' table. |
| `ReturnedInterbankSettlementAmount` | object | Yes      | -              | -       | Amount of money to be moved between the instructing agent and the instructed agent in the returned instruction. Refer to the 'ActiveOrHistoricCurrencyAndAmount' table.        |
| `ReturnReasonInformation`           | array  | No       | -              | -       | Provides detailed information on the return reason. Contains 1 to 10 items. Refer to the 'PaymentReturnReason' table.                                                          |

##### ActiveOrHistoricCurrencyAndAmount (OriginalInterbankSettlementAmount and ReturnedInterbankSettlementAmount)

| Field      | Type    | Required | Constraints      | Pattern      | Description                                             |
| ---------- | ------- | -------- | ---------------- | ------------ | ------------------------------------------------------- |
| `Amount`   | decimal | Yes      | -                 | -            | Amount of money.                                        |
| `Currency` | string  | Yes      | 3-3 length       | `^[A-Z]{3}$` | Currency of money. Three-letter ISO 4217 currency code. |

##### PaymentReturnReason

| Field                   | Type   | Required | Min-Max length | Pattern | Description                                                                                           |
| ----------------------- | ------ | -------- | -------------- | ------- | ----------------------------------------------------------------------------------------------------- |
| `ReasonCode`            | string | No       | 1-4            | -       | Specifies the reason for the return, as published in an external reason code list.                    |
| `Originator`            | object | No       | -              | -       | Party that issues the return. Refer to the 'PartyIdentification' table.                                    |
| `AdditionalInformation` | array  | No       | -              | -       | Further information on the return reason. Contains 1 to 10 items, each 1 to 105 characters in length. |

##### PartyIdentification (Originator)

| Field            | Type   | Required | Min-Max length | Pattern | Description                                                              |
| ---------------- | ------ | -------- | -------------- | ------- | ------------------------------------------------------------------------ |
| `Name`           | string | No       | 1-140          | -       | Unique and unambiguous identification of a party.                            |
| `Identification` | object | No       | -              | -       | Unique and unambiguous identification of a party. Refer to the 'Party' table. |

##### Party

| Field                        | Type   | Required | Min-Max length | Pattern | Description                                                                                         |
| ---------------------------- | ------ | -------- | -------------- | ------- | --------------------------------------------------------------------------------------------------- |
| `OrganisationIdentification` | object | No       | -              | -       | Unique and unambiguous way to identify an organisation. Refer to the 'OrganisationIdentification' table. |

##### OrganisationIdentification

| Field    | Type   | Required | Min-Max length | Pattern                                                    | Description                                       |
| -------- | ------ | -------- | -------------- | ---------------------------------------------------------- | ------------------------------------------------- |
| `AnyBIC` | string | No       | -              | `[A-Z0-9]{4,4}[A-Z]{2,2}[A-Z0-9]{2,2}([A-Z0-9]{3,3}){0,1}` | Business identification code of the organisation. |
