<h2 className="no-toc">
  Choosing the right identifier
</h2>

When working with ClearBank APIs and webhooks, you might encounter several different identifiers relating to the same payment.

For example, a payment journey might include:

- A payment reference such as `EndToEndIdentification` or `EndToEndId`
- A ClearBank identifier such as `PaymentId` or `TransactionId`
- A scheme or network reference, where applicable, such as a `UETR`

Although these identifiers might refer to the same payment journey, they serve different purposes and should not be treated as interchangeable.

<Callout colour="green">
  <p>For definitions of individual identifiers, see the <b><a href="/eu/docs/api/technical-reference">Technical Reference</a></b>.</p>
</Callout>

## Which identifier should I use?

| I want to... | Use |
|--------------|-----|
| Reference an account | `AccountId` |
| Reference a customer | `CustomerId` |
| Reference a payment instruction | `PaymentId` |
| Reference a transaction on an account | `TransactionId` |
| Reference a Direct Debit mandate | `MandateId` or `DirectDebitMandateId` |
| Reference an earlier transaction | `OriginalTransactionId` |
| Match a payment to my own records | The applicable payment reference, such as `EndToEndIdentification` or `EndToEndId` |
| Trace an API request | `X-Request-Id` |
| Investigate an API call | `X-Correlation-Id` |
| Trace an applicable scheme or network payment | `UETR`, where provided |

## Identifier categories

Identifiers generally fall into the following categories.

### API request identifiers

API request identifiers help you trace requests and responses.

| Identifier | Purpose |
|------------|---------|
| `X-Request-Id` | Identifies a single API request. You supply it with the request |
| `X-Correlation-Id` | Returned in the API response. Used when investigating an API call |
<br/>
<Callout colour="blue">
Make sure you include the <b>X-Request-Id</b> and <b>X-Correlation-Id</b> when you raise an issue with Client Services or API Integration, so that we can identify the specific API call and events involved.
</Callout>

### Customer and account identifiers

These identify your customers, accounts and mandates.

| Identifier | Identifies |
|------------|------------|
| `AccountId` | An account |
| `CustomerId` | A customer |
| `MandateId` | A mandate |
| `DirectDebitMandateId` | A Direct Debit mandate |

`AccountId` and `CustomerId` can also appear in other account activity, such as when an account is created, updated or suspended.

### Payment and transaction identifiers

These are generated by ClearBank to identify a payment or a transaction.

| Identifier | Identifies |
|------------|------------|
| `PaymentId` | A payment, which is an instruction to move money. Use this to identify and track the payment you initiated |
| `TransactionId` | An individual credit or debit transaction on an account. Use this to identify what happened on the account, rather than the payment instruction |
| `OriginalTransactionId` | An earlier transaction |

### Payment references

These fields identify a payment across the payment chain. The reference is originally supplied by the initiating party. The field name, and in some cases the value, depends on the payment scheme and the direction of the payment.

| Identifier | Notes |
|------------|-------|
| `EndToEndIdentification` | A payment reference supplied by the initiating party, used to match activity to your own records. `PaymentId` is the ClearBank equivalent, generated by ClearBank |
| `EndToEndId` | The same concept under a different field name |
| `EndToEndTransactionId` | The same concept, with a value that depends on the scheme and direction |

Use these to match ClearBank activity with your own records.

### Scheme-related identifiers

A payment scheme or ClearBank's scheme-specific processing may provide additional references, depending on the payment type.

| Identifier | Stands for | Use |
|------------|------------|-----|
| `UETR` | Unique End-to-end Transaction Reference | A scheme or network reference, where supported, used to identify the payment in scheme or reporting data. It's different from `EndToEndIdentification` and `EndToEndId`, which are assigned by the initiating party |
| `SchemeEndToEndId` | Scheme End-to-End ID | Scheme-specific end-to-end reference for applicable multi-currency payments |

### Security identifiers

| Identifier | Use |
|------------|-----|
| `Nonce` | A cryptographically secure random number generated by ClearBank for each webhook, used in webhook delivery acknowledgements. It is not a payment, transaction, or reconciliation identifier, and should be returned in your webhook response to acknowledge receipt. Nonces are not necessarily unique and should not be used for deduplication.|

## Payment journey example

The following example illustrates how identifiers can appear throughout the lifecycle of a payment.

```text
You initiate a payment
│
├─ Applicable payment reference
│  ├─ EndToEndIdentification
│  └─ EndToEndId
│
▼

ClearBank receives the payment
│
├─ PaymentId
│
▼

Transaction processing
│
├─ TransactionId
│
▼

SEPA or T2 processing
│
├─ UETR, where supported
├─ InstructionIdentification, where applicable
└─ SchemeEndToEndId, where applicable
│
▼

Webhook generated
│
├─ PaymentId, where applicable
├─ TransactionId, where applicable
├─ EndToEndIdentification or EndToEndId, where applicable
└─ Nonce
```

Not every payment flow contains every identifier. The identifiers available depend on the payment type, payment scheme and webhook event.

## Identifiers in webhooks

A webhook can contain several identifiers. The available fields depend on the webhook type, payment scheme and payment direction.

Use the identifier according to what you are trying to identify:

| Identifier | Identifies |
|------------|------------|
| `PaymentId` | A payment instruction |
| `TransactionId` | An individual credit or debit transaction on an account |
| `EndToEndIdentification` or `EndToEndId` | A payment reference used across the payment chain, where supported |
| `UETR` | A scheme or network payment reference, where provided |
| `Nonce` | The webhook delivery acknowledgement value |

## Using identifiers across webhooks and endpoints

Identifiers such as `PaymentId`, `TransactionId` and the applicable payment reference can appear in more than one webhook or endpoint for the same payment. Use them to help identify events that relate to the same payment, account or transaction.

Store the identifiers you receive against your own records so you can match later events to them.
