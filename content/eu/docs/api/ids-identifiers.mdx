<h2 className="no-toc">
  Choosing the right identifier
</h2>

When working with ClearBank APIs and webhooks, you might encounter several different identifiers relating to the same payment.

For example, a payment journey might include:

- A payment reference such as `EndToEndIdentification` or `EndToEndId`
- A ClearBank identifier such as `PaymentId` or `TransactionId`
- A scheme or network reference, where applicable, such as a `UETR`

Although these identifiers might refer to the same payment journey, they serve different purposes and should not be treated as interchangeable.

<Callout colour="blue">
  <p>For definitions of individual identifiers, see the <a href="/eu/docs/api/technical-reference">Technical Reference</a>.</p>
</Callout>

## Which identifier should I use?

| I want to... | Use |
|--------------|-----|
| Reference an account | `AccountId` |
| Reference a customer | `CustomerId` |
| Reference a payment | `PaymentId` |
| Reference a transaction | `TransactionId` |
| Reference a Direct Debit mandate | `MandateId` or `DirectDebitMandateId` |
| Reference an earlier transaction | `OriginalTransactionId` |
| Match a payment to my own records | The applicable payment reference, such as `EndToEndIdentification` or `EndToEndId` |
| Trace an API request | `X-Request-Id` |
| Investigate an API call | `X-Correlation-Id` |
| Trace an applicable scheme or network payment | `UETR`, where provided |

## Identifier categories

Identifiers generally fall into five categories.

### Tracking identifiers

Tracking identifiers help trace requests and events.

| Identifier | Purpose |
|------------|---------|
| `X-Request-Id` | Identifies a single, specific API HTTP request |
| `X-Correlation-Id` | A ClearBank-generated response identifier used when investigating an API call |

### Entity identifiers

Entity identifiers identify ClearBank resources and entities.

| Identifier | Identifies |
|------------|------------|
| `AccountId` | An account |
| `CustomerId` | A customer |
| `PaymentId` | A payment |
| `TransactionId` | A transaction |
| `MandateId` | A mandate |
| `DirectDebitMandateId` | A Direct Debit mandate |
| `OriginalTransactionId` | An earlier transaction |

### Payment references

These fields identify a payment or transaction across the payment chain. Depending on the payment scheme and direction, the value may be supplied by the initiating party or populated from scheme or instruction data.

| Identifier |
|------------|
| `EndToEndId` |
| `EndToEndTransactionId` |
| `EndToEndIdentification` |

These identifiers are commonly used to reconcile ClearBank activity with internal systems and records.

### Scheme-related identifiers

A payment scheme or ClearBank's scheme-specific processing may provide additional references, depending on the payment type:

#### EU scheme-related identifiers

| Identifier | Use |
|------------|-----|
| `UETR` | End-to-end reference for an applicable payment transaction |
| `SchemeEndToEndId` | Scheme-specific end-to-end reference for applicable multi-currency payments |

### Security identifiers

| Identifier | Use |
|------------|-----|
| `Nonce` | A cryptographically secure random number generated by ClearBank for each webhook, used in webhook delivery acknowledgements. It is not a payment, transaction, or reconciliation identifier, and should be returned in your webhook response to acknowledge receipt. |

Use `PaymentId`, `TransactionId`, or the applicable payment reference to identify the underlying payment activity.


## Understanding payment identifiers

Several identifiers might exist for the same payment journey. Each identifier serves a different purpose.

### Payment references

Payment references can identify a payment or transaction across the payment chain. Depending on the payment scheme and direction, the value may be supplied by the initiating party or populated from scheme or instruction data.

Common EU field names include:

```text
EndToEndIdentification
EndToEndId
```

### ClearBank identifiers

ClearBank-generated identifiers can refer to different resources involved in a payment journey:

```text
PaymentId
TransactionId
AccountId
CustomerId
```

These identifiers identify ClearBank resources and activities.

### Scheme identifiers

A payment scheme or ClearBank's scheme-specific processing may provide additional references, depending on the payment type:

```text
UETR
InstructionIdentification
SchemeEndToEndId
```

These identifiers are available only for applicable payment types, schemes and webhook events. Their source depends on the payment flow.
## Payment journey example

The following example illustrates how identifiers can appear throughout the lifecycle of a payment.

```text
You initiate a payment
│
├─ Applicable payment reference
│  ├─ EndToEndIdentification
│  └─ EndToEndId
│
▼

ClearBank receives the payment
│
├─ PaymentId
│
▼

Transaction processing
│
├─ TransactionId
│
▼

SEPA or T2 processing
│
├─ UETR, where supported
├─ InstructionIdentification, where applicable
└─ SchemeEndToEndId, where applicable
│
▼

Webhook generated
│
├─ PaymentId, where applicable
├─ TransactionId, where applicable
├─ EndToEndIdentification or EndToEndId, where applicable
└─ Nonce


Reconciliation
```

Not every payment flow contains every identifier.

The identifiers available depend on the payment type, payment scheme and webhook event.

## Common points of confusion

### PaymentId and TransactionId

These identifiers represent different concepts.

| PaymentId | TransactionId |
|------------|--------------|
| Identifies a payment instruction | Identifies a transaction |
| Used when referring to the payment | Used when referring to the transaction resulting from or associated with payment processing |


A payment journey might contain both identifiers.

### EndToEndIdentification and PaymentId

These identifiers originate from different sources.

| EndToEndIdentification | PaymentId |
|------------------------|-----------|
| Payment reference assigned by the initiating party where supported | ClearBank payment identifier |
| Used to correlate activity with your records | Used when working with ClearBank APIs and webhook data |

Many organisations use `EndToEndIdentification` to reconcile payments with internal systems and `PaymentId` when working with ClearBank APIs and webhook data.

### X-Request-Id and X-Correlation-Id

These identifiers are used for tracing and troubleshooting individual API requests and related API messages with a shared origin.

| X-Request-Id | X-Correlation-Id |
|--------------|------------------|
| Supplied with the API request | Returned in the API response |
| Used to identify the request | Used when investigating the API call |

### EndToEndIdentification and UETR

These identifiers have similar names but serve different purposes.

| EndToEndIdentification | UETR |
|------------------------|------|
| Payment reference assigned by the initiating party where supported | Scheme or network reference where supported |
| Used to correlate activity with your records | Used to identify the payment in applicable scheme or reporting data |

### Working with webhook data

A webhook can contain several identifiers. The available fields depend on the webhook type, payment scheme and payment direction.

Use the identifier according to what you are trying to identify:

| Identifier | Identifies |
|------------|------------|
| `PaymentId` | A ClearBank payment instruction |
| `TransactionId` | A ClearBank transaction |
| `EndToEndIdentification` or `EndToEndId` | A payment reference used across the payment chain, where supported |
| `UETR` | A scheme or network payment reference, where provided |
| `Nonce` | The webhook delivery acknowledgement value |

## Reconciliation example

A common reconciliation approach is:

1. Submit a payment with the applicable payment reference.
2. Store that reference with your internal payment record.
3. Receive webhook events.
4. Match the corresponding payment reference in the webhook to your internal record.
5. Use `PaymentId`, `TransactionId` and any applicable scheme identifier for further investigation or reconciliation.
